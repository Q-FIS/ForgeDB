# [W1.4] Robustness: the things that kill servers
labels: week:1, size:S
groups: A, B

**Size:** S (1 day) · **Needs:** W1.2

## What is this, in plain words?
Most servers don't die from big bugs; they die from small things: a client that
disconnects at the wrong moment, an interrupted system call, a port that's
"still in use". You hunt for these on purpose, with tools, and write down what
you find. Your group's server must survive all of them before week 2 builds on it.

## Step by step
1. **SIGPIPE:** temporarily remove the `SIG_IGN` and `MSG_NOSIGNAL` from your code. Run the echo test. What happens? Look at the server's exit status (`echo $?` when you run it by hand). Put them back.
2. **EINTR:** a system call can fail with `EINTR` when a signal arrives in the middle of it. Make `recv_some` and `send_all` retry on `EINTR` instead of throwing.
3. **Restart:** start the server, connect with `nc`, stop the server with Ctrl-C, and start it again straight away. Does it work? Comment out `SO_REUSEADDR` and try again. Run `ss -tan | grep <port>` to see the `TIME_WAIT` connections.
4. **Bad arguments:** a missing `--port`, `--port abc`, `--port 99999`: each must print a clear message and exit with code 2, not crash.
5. Write `docs/<group>-week1-notes.md` (one page): for each of the four things above, what you saw and why.

## Done when
- [ ] `recv_some` and `send_all` retry on `EINTR`, with a unit test using a signal (or a clear explanation of why it's hard to test, in the notes)
- [ ] Bad arguments exit with code 2 and a message
- [ ] `docs/<group>-week1-notes.md` is merged
