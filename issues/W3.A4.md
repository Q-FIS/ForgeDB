# [W3.A4] Graceful shutdown on SIGTERM
labels: week:3, size:M
groups: A

**Size:** M (2-3 days) · **Needs:** W3.A3

## What is this, in plain words?
When a server is stopped (deploying a new version, say), it gets `SIGTERM`. A
**graceful** shutdown stops accepting new connections, **finishes the requests
already in progress**, and then exits. Signals and threads together are tricky:
a signal can arrive in any thread, at any moment, and almost nothing is safe
to do inside a signal handler.

## Step by step
1. The safe pattern: **block** `SIGTERM` and `SIGINT` in every thread (`pthread_sigmask` at the very start of `main`, before creating any thread, since threads inherit the mask). Then make one dedicated thread wait for them with `sigwait`. When it returns, that thread starts the shutdown, using normal code, not a signal handler.
2. Shutting down:
   1. stop accepting: `shutdown(listener.fd(), SHUT_RDWR)` wakes the main thread out of `accept` (it fails), so it leaves its loop;
   2. let the workers finish: destroy the `WorkerPool` (which closes the queue and joins the workers);
   3. `return 0` from `main`.
3. Requests already being served must complete. Keep-alive connections that are idle may be closed.
4. In `tests/CMakeLists.txt`, uncomment the `a_shutdown` line.

## How to test it
`tests/shutdown_test.py` starts 5 requests to `/sleep?ms=1000`, sends `SIGTERM` 200 ms later, and checks that all 5 get 200, the server exits with code 0 within 3 s, and new connections are refused.
