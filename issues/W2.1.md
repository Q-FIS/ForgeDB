# [W2.1] Parse an HTTP request (no copies)
labels: week:2, size:M
groups: A, B

**Size:** M (2-3 days) · **Needs:** nothing (pure parsing: no sockets) · **Language topic:** `std::string_view`, `std::optional`, `enum class`

## What is this, in plain words?
An HTTP request is just text:
```
POST /echo HTTP/1.1\r\n
Host: localhost\r\n
Content-Length: 11\r\n
\r\n
hello world
```
You turn that text into a C++ struct. The input comes from **anyone on the
network**, so you must assume it's broken or hostile: missing parts, huge
lines, weird characters. Bugs in parsers like this are a classic source of
security holes, which is why next week a fuzzer throws thousands of broken
requests at it.

## What you must give back
In `src/http_request.hpp/.cpp`, a function that parses the **head** (everything up to and including the blank line):
```cpp
enum class Method { Get, Post, Put, Delete, Head, Other };

struct Request {
    Method method;
    std::string_view target;    // "/echo" or "/sleep?ms=5"
    std::string_view version;   // "HTTP/1.1"
    std::vector<std::pair<std::string_view, std::string_view>> headers;
    std::optional<std::string_view> header(std::string_view name) const;   // case-insensitive
};

enum class ParseError { Malformed, HeadersTooLarge };

// `head` is the bytes up to and including "\r\n\r\n".
// The string_views in Request point INTO `head`: no copies.
std::variant<Request, ParseError> parse_request_head(std::string_view head);
```

## Step by step
1. Split off the **request line** (up to the first `\r\n`): exactly three parts separated by single spaces. The method is letters only; the target must start with `/`; the version must be `HTTP/1.1` or `HTTP/1.0`. Anything else → `ParseError::Malformed`.
2. Each **header line** is `Name: value`. The name is non-empty, with no spaces; trim spaces around the value. A line without `:` → `Malformed`.
3. `header(name)`: compare names ignoring case (`Content-Length` = `content-length`).
4. If `head` is longer than 8 KiB → `ParseError::HeadersTooLarge`. (W2.4 also stops *reading* at 8 KiB, so a huge header never even reaches memory.)
5. Write a helper `std::optional<std::size_t> content_length(const Request&)`: no header → 0; digits only, at most 10 digits → the number; anything else (`-1`, `abc`, `10 10`) → `std::nullopt`, which means 400.

## Watch out for
- A `string_view` doesn't own its text. If the buffer it points into is freed or reused, the view points at garbage. ASan will tell you, which is exactly why we run it.
- Never use `std::stoi` on untrusted input without checking: it throws on non-digits and on overflow. Parse the digits yourself, or use `std::from_chars`.

## How to test it
`tests/test_http_request.cpp`: at least 20 cases. A valid GET and POST; header names in different cases; no headers; spaces around values; a missing version; two spaces in the request line; a header without a colon; a 9 KB head; `Content-Length` values `0`, `11`, `-1`, `abc`, `99999999999999999999`.
