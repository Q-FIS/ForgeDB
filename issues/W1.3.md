# [W1.3] The echo client
labels: week:1, size:S
groups: A, B

**Size:** S (1 day) · **Needs:** W1.1

## What is this, in plain words?
A client that sends a file to the echo server and checks that exactly the same
bytes come back. The trap: if you send the whole 100 MB before reading
anything, the server's replies fill up the buffers, the server stops reading,
and both programs wait for each other forever (a **deadlock**). So you must
read while you send.

## The contract
`apps/echo_client.cpp`, run as `<g>_echo_client --host 127.0.0.1 --port <N> --file <path>`.
Exit code **0** if the echo matches the file, **1** if not (print what differed), **2** for bad arguments.

## Step by step
1. Parse the arguments. Read the whole file into a `std::vector<char>` (use `std::ifstream` in binary mode, or `open`/`read`).
2. `connect_tcp(host, port)`.
3. **Send and receive at the same time:** start a `std::thread` that `send_all`s the file, then calls `shutdown(fd, SHUT_WR)`. That tells the server "I'm done sending" without closing the socket, so you can still read. Meanwhile, the main thread reads with `recv_some` into a second vector until it returns 0.
4. Join the thread. Compare the two vectors, and exit 0 or 1.

## Watch out for
- `std::thread` must be `join()`ed before it is destroyed, or the program aborts. (Or use `std::jthread`, which joins itself: it's what week 3 uses.)
- `shutdown(SHUT_WR)` is not `close`. Learn the difference.

## How to test it
`ctest --preset debug -R echo --output-on-failure`: the last check runs your client against your server with a 5 MB file.
