# [W2.2] Build HTTP responses
labels: week:2, size:S
groups: A, B

**Size:** S (1 day) · **Needs:** nothing

## What is this, in plain words?
The other direction: turn a status code, some headers and a body into the exact
bytes to send. Small, but every response the server ever sends goes through it.

## What you must give back
In `src/http_response.hpp/.cpp`:
```cpp
struct Response {
    int status = 200;
    std::string content_type = "text/plain";
    std::string body;
    bool close = false;   // send "Connection: close" and close the connection afterwards
};

std::string reason_phrase(int status);        // 200 -> "OK", 404 -> "Not Found", ...
std::string serialize(const Response& r);     // the exact bytes to send
Response error_response(int status);          // a small text body, e.g. "404 Not Found\n"
```

## Step by step
1. `reason_phrase` for 200, 400, 404, 405, 413, 431, 500 and 503 (look them up in RFC 9110 section 15).
2. `serialize`: `HTTP/1.1 <status> <reason>\r\n`, then `Content-Type: ...\r\n`, `Content-Length: <body size>\r\n`, `Connection: close\r\n` if `close` is set, then a blank line `\r\n`, then the body.
3. `error_response`: errors 400, 413 and 431 should set `close = true`. After a malformed request we can't know where the next request would start, so the safe thing is to close.

## How to test it
`tests/test_http_response.cpp`: the exact bytes for a 200 with a body, an empty body (`Content-Length: 0`), a 404, and a response with `close`.
