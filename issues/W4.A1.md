# [W4.A1] Idle timeout for keep-alive connections
labels: week:4, size:S
groups: A

**Size:** S (1 day) · **Needs:** W3.A2

## What is this, in plain words?
In a thread pool, each keep-alive connection **occupies a worker** while it
waits for the client's next request. A client that connects and then does
nothing blocks a worker forever. With 8 workers, 8 idle clients take the whole
server down. The fix: close connections that stay silent for too long.

## Step by step
1. Add `--idle-timeout-ms N` (default 5000).
2. Before each `recv` while waiting for a request, set a receive timeout on the socket: `setsockopt(fd, SOL_SOCKET, SO_RCVTIMEO, ...)` with a `timeval`. Or use `poll()` with a timeout before reading.
3. When the timeout fires, `recv` fails with `EAGAIN`/`EWOULDBLOCK`: close the connection quietly. That isn't an error worth printing.
4. In `tests/CMakeLists.txt`, uncomment `a_idle_timeout`.

## How to test it
`tests/idle_timeout_test.py` with `--idle-timeout-ms 500`: a silent connection must be closed after about 0.5 s; a connection that sends a request every 200 ms must stay open.

## Done when
