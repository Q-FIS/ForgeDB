# [W3.B1] An Epoll class, and non-blocking sockets
labels: week:3, size:S
groups: B

**Size:** S (1 day) · **Needs:** nothing · **Language topic:** RAII again, `enum class`, `std::span`

## What is this, in plain words?
`epoll` is how one thread can watch thousands of sockets: you tell the kernel
which sockets you care about, and `epoll_wait` tells you which ones are ready
to read or write. You wrap it in a small RAII class, so the rest of the event
loop reads like plain C++.

## What you must give back
`src/epoll.hpp/.cpp`:
```cpp
void set_nonblocking(int fd);          // fcntl(F_GETFL), then F_SETFL with O_NONBLOCK

class Epoll {
public:
    Epoll();                           // epoll_create1(EPOLL_CLOEXEC)
    ~Epoll();                          // closes it (or hold a Socket-like RAII fd)
    void add(int fd, uint32_t events);     // EPOLL_CTL_ADD
    void modify(int fd, uint32_t events);  // EPOLL_CTL_MOD
    void remove(int fd);                   // EPOLL_CTL_DEL
    // Waits up to timeout_ms (-1 = forever). Returns the ready events.
    std::span<epoll_event> wait(int timeout_ms);
};
```

## Step by step
1. Write `set_nonblocking`.
2. Write the class. `wait` keeps an internal `std::vector<epoll_event>` (say 256 entries), calls `epoll_wait`, and returns a span over the filled part. Retry on `EINTR`.
3. Use **level-triggered** mode (the default, no `EPOLLET`). It's simpler and harder to get wrong. Learn first explains the difference.

## How to test it
`tests/test_epoll.cpp`: create a `pipe`, add its read end with `EPOLLIN`; `wait(0)` returns nothing; write a byte; now `wait(0)` returns that fd. A non-blocking `recv` on an empty socket fails with `EAGAIN`.
