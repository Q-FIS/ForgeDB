# [W2.4] The HTTP server: read whole requests, keep-alive, limits
labels: week:2, size:M
groups: A, B

**Size:** M (2-3 days, good for a pair) · **Needs:** W1.2, W2.1, W2.2, W2.3

## What is this, in plain words?
This puts it all together in `apps/http_server.cpp`. The hard part is
**reading**: TCP gives you bytes in random pieces, so you collect bytes until
you have the whole head (up to the blank line), then exactly `Content-Length`
more bytes of body. A request can arrive in 3 pieces, or 2 requests can arrive
in one piece. Your code must handle both.

## The contract
`<g>_http_server --port <N> --root <dir>`. See `issues/START_HERE.md`, section 4, for every response. One connection at a time is fine this week (week 3 adds concurrency).

## Step by step
1. Parse `--port` and `--root`. Listen like the echo server.
2. For each connection, keep a `std::string buffer` and loop:
   1. **Read the head:** append from `recv_some` until the buffer contains `\r\n\r\n`. If the buffer passes **8 KiB** without one → send 431 and close. If the client closes → close.
   2. Parse the head (W2.1). Malformed → 400 and close.
   3. `content_length(...)`: invalid → 400 and close; **over 1 MiB → 413 and close, before reading the body** (never read a body you won't accept).
   4. **Read the body:** you may already have some of it in the buffer after the head. Keep reading until you have exactly that many bytes.
   5. `handle(...)` (W2.3), then `send_all(serialize(response))`.
   6. **Remove** this request's bytes from the front of the buffer. **Keep anything after them**: it's the start of the next request (that's keep-alive).
   7. If the request said `Connection: close`, or the response is an error that closes, close the connection. Otherwise loop for the next request.
3. Catch `std::system_error` around each connection, as in the echo server.
4. Delete the placeholder.

## Watch out for
- Step 2.6 is the classic bug: throwing away the whole buffer loses the start of the next request.
- Never trust `Content-Length` until you've checked it's sane (W2.1's helper).

## How to test it
```bash
ctest --preset debug -R http --output-on-failure
curl -v http://localhost:8080/health
curl -v --data 'hello' http://localhost:8080/echo
```
`tests/http_test.py` checks every row of the contract, plus keep-alive, `Connection: close`, and a request split across 3 packets. `tests/http_fuzz.py` sends 3,000 broken requests (run it with more by hand: `python3 tests/http_fuzz.py <server> 20000`).
