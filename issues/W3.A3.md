# [W3.A3] Acceptor, 503 backpressure and /sleep
labels: week:3, size:S
groups: A

**Size:** S (1 day) · **Needs:** W3.A2

## What is this, in plain words?
Connect the pieces. The main thread accepts connections and hands them to the
pool. If the pool's queue is full, the server answers **503 Service
Unavailable** straight away and closes. That's **backpressure**: telling
clients "too busy, try later" is far better than making them wait forever.
You also add `/sleep`, a fake slow request used in every load test.

## Step by step
1. In `apps/http_server.cpp`: parse `--workers N` (default 8) and `--queue N` (default 64), and create the `WorkerPool`.
2. Main loop: `accept_client`, then `if (!pool.submit(std::move(client)))`. But the client was moved... Design `submit` so that on failure it gives the socket back (return it, or take it by reference), and you can then send `serialize(error_response(503))` on it and close it.
3. Add the route `GET /sleep?ms=N` in `routes.cpp`: parse N (0 to 10,000; otherwise 400), `std::this_thread::sleep_for(std::chrono::milliseconds(N))`, then 200.
4. In `tests/CMakeLists.txt`, uncomment the `a_backpressure` line.

## How to test it
`ctest --preset debug -R a_ --output-on-failure`. The backpressure test starts the server with `--workers 1 --queue 1`, and sends 10 slow requests at once: at least one must get 200, and most must get 503 quickly.
