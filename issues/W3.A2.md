# [W3.A2] The worker pool (std::jthread)
labels: week:3, size:M
groups: A

**Size:** M (2-3 days) · **Needs:** W3.A1 · **Language topic:** `std::jthread`, `std::stop_token`, lambdas, `std::function`

## What is this, in plain words?
N worker threads, each looping: take a connection from the queue, handle all its
requests (your week-2 code), close it, repeat. With 8 workers, 8 clients are
served at the same time instead of one.

## What you must give back
`src/worker_pool.hpp/.cpp`:
```cpp
class WorkerPool {
public:
    WorkerPool(std::size_t workers, std::size_t queue_capacity,
               std::function<void(Socket)> handle_connection);
    ~WorkerPool();                   // closes the queue and joins every worker
    bool submit(Socket client);      // false if the queue is full (the caller answers 503)
};
```

## Step by step
1. In the constructor, start `workers` threads with `std::jthread`. Each runs: `while (auto client = queue.pop()) { handle_connection(std::move(*client)); }`.
2. Catch every exception inside the loop (and print it), so one bad connection never kills a worker thread.
3. `~WorkerPool`: `queue.close()`. Then the workers' loops end, and `std::jthread` joins them automatically as they are destroyed.
4. Move your week-2 per-connection code into a function `void serve_connection(Socket client, const std::filesystem::path& root)` in `src/`, so the pool can call it.

## How to test it
`tests/test_worker_pool.cpp`: submit 100 jobs that each increment an atomic counter; destroy the pool; the counter is 100. Submit to a pool with 1 worker and a queue of 1 while the worker is busy: the third `submit` returns false. Run on `tsan`.

## Done when
