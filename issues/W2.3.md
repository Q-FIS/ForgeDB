# [W2.3] Routes: /health, /echo and static files
labels: week:2, size:S
groups: A, B

**Size:** S (1 day) · **Needs:** W2.1 and W2.2 (you can start with your own small structs, and switch when they're merged)

## What is this, in plain words?
Decide what to answer for each request. Most of it is simple, except **static
files**: the path comes from a stranger, and `GET /static/../../etc/passwd` must
**never** send your password file. That's a classic attack called path
traversal, and you'll defend against it on purpose.

## What you must give back
In `src/routes.hpp/.cpp`:
```cpp
// Decide the response for one complete request (head + body).
Response handle(const Request& req, std::string_view body, const std::filesystem::path& root);
```
| Request | Response |
| --- | --- |
| `GET /health` | 200, `application/json`, body `{"status":"ok"}` |
| `POST /echo` | 200, the body sent back |
| `GET /static/<file>` | 200 with the file's contents from `root`, or 404 |
| a known path with another method | 405 |
| anything else | 404 |

## Step by step
1. Split the target at `?`: the path is before it, the query after (you'll need the query for `/sleep?ms=5` in week 3).
2. `/health` and `/echo`: straightforward.
3. `/static/<file>`:
   - take the part after `/static/`;
   - **refuse** (400) anything containing a `..` segment, a NUL byte, or starting with `/`;
   - build `root / file`, then double-check it: `std::filesystem::weakly_canonical(full)` must still start with `weakly_canonical(root)`;
   - if it's a regular file, read it (`std::ifstream`, binary) and return 200 with `text/html` for `.html` and `text/plain` otherwise; if not, 404.

## How to test it
`tests/test_routes.cpp`, using `tests/www` from the repo root as the root: `/health`, `/echo`, `/static/index.html`, a missing file → 404, `/static/../CMakeLists.txt` → refused, `DELETE /health` → 405.

## Done when
- [ ] The tests pass, including at least 4 path-traversal attempts
