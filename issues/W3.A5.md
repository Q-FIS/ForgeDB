# [W3.A5] Load test: how many workers?
labels: week:3, size:S
groups: A

**Size:** S (1 day) · **Needs:** W3.A3

## What is this, in plain words?
Measure how the thread pool behaves under load, and find a good number of
workers. This is also your first use of `wrk`, the load-testing tool.

## Step by step
1. In `tests/CMakeLists.txt`, uncomment `a_concurrency`, and make it pass on `debug` and `tsan`.
2. Build **release** (`cmake --preset release && cmake --build --preset release -j`). Never measure the debug build: sanitizers make it 2-10x slower.
3. Start the server with `--workers N`, then run `wrk -t4 -c<C> -d20s --latency 'http://127.0.0.1:8080/sleep?ms=5'` for N = 1, 2, 4, 8, 16 and C = 10, 100, 1000.
4. Record requests per second, p50 and p99 (wrk prints them with `--latency`) in `docs/a-week3-load.md`, as a table.
5. Explain the numbers: with a 5 ms handler, one worker can do at most 200 requests per second. Do your numbers match? (That's **Little's law**: requests in progress = throughput × time per request.)

## Done when
- [ ] `a_concurrency` passes on `debug` and `tsan`
- [ ] `docs/a-week3-load.md` with the table and your explanation
