# [W3.B2] The connection state machine
labels: week:3, size:M
groups: B

**Size:** M (2-3 days) · **Needs:** W2.4 · **Language topic:** `enum class`, classes with clear state

## What is this, in plain words?
In an event loop, one thread juggles every connection, so **no connection may
ever wait**. Each connection becomes a small object that remembers where it
is: still reading the request, or still writing the response. When epoll says
"this socket is ready", you push that connection one step forward and move on.
This object is a **state machine**.

## What you must give back
`src/connection.hpp/.cpp`:
```cpp
class Connection {
public:
    enum class State { Reading, Writing, Closing };
    Connection(Socket socket, std::filesystem::path root);

    // Call when epoll says the socket is readable. Reads what is available
    // (until EAGAIN), and when a whole request has arrived, prepares the response.
    void on_readable();
    // Call when epoll says the socket is writable. Writes as much as the
    // kernel accepts (until EAGAIN).
    void on_writable();

    State state() const;
    int fd() const;
};
```

## Step by step
1. **Reading:** `recv` in a loop into the input buffer until it fails with `EAGAIN` (no more data **for now**) or returns 0 (the client closed → `Closing`). Your recv helper must treat `EAGAIN` as "stop for now", not as an error.
2. After reading, check whether the buffer holds a complete request: reuse your week-2 logic (head up to `\r\n\r\n`, then `Content-Length` bytes). Refactor it out of the blocking loop into a function that just *looks* at a buffer and says "not complete yet", "complete: this many bytes", or "error: 400/413/431".
3. When complete: `handle(...)`, then put `serialize(response)` into the output buffer, and switch to `Writing`.
4. **Writing:** `send` as much as the kernel accepts. If everything is sent, then either go back to `Reading` (keep-alive; there may already be the next request in the input buffer!), or go to `Closing`.

## How to test it
`tests/test_connection.cpp`: connect a `socketpair` and drive a `Connection` by calling its methods directly: write half a request → still `Reading`; write the rest → `Writing`; read the response from the other end. Two requests in one write → two responses.
