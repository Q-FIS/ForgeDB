# [W4.B2] Graceful shutdown with signalfd
labels: week:4, size:S
groups: B

**Size:** S (1 day) · **Needs:** W3.B3

## What is this, in plain words?
On `SIGTERM`: stop accepting, finish the responses in progress, then exit with
code 0. The event-loop way to receive a signal is elegant: turn it into a file
descriptor (`signalfd`) and watch it with epoll like any other socket, so no
signal handler is needed at all.

## Step by step
1. At the start of `main`, block `SIGTERM` and `SIGINT` (`sigprocmask`), create a `signalfd` for them, and add it to epoll with `EPOLLIN`.
2. When it becomes readable: read the `signalfd_siginfo`, remove and close the listener (no new connections), and set `shutting_down = true`.
3. While shutting down: connections that are idle (`Reading` with an empty buffer) are closed right away; the others finish their current response, then close. When no connections are left, leave the loop and return 0.
4. Uncomment `b_shutdown` in `tests/CMakeLists.txt` **only once it passes** (see below), so CI stays green.

## How to test it
`tests/shutdown_test.py` starts 5 requests to `/sleep?ms=1000` and sends `SIGTERM` 200 ms later. **Careful:** in your event loop, `/sleep` blocks the whole loop, so those 5 requests are served one after another (that's 5 seconds!). The test expects shutdown within 3 seconds. So this test will **fail**, and that's the point. Write down why in the PR, and either (a) make `/sleep` non-blocking, using a timer instead of `sleep_for`, which is the event-loop way, or (b) leave it failing, with a note for the week-5 design. Discuss it with your group.
