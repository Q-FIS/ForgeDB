# [W4.A2] Timing every request
labels: week:4, size:S
groups: A

**Size:** S (1 day) · **Needs:** W3.A3 · **Language topic:** `std::chrono`

## What is this, in plain words?
Before the race, add a simple log line per request, so you can see what the
server is doing and how long each request takes inside the server.

## Step by step
1. Measure each request with `std::chrono::steady_clock` (never `system_clock` for durations; Learn first says why).
2. With `--log`, print one line per request to stderr: `GET /health 200 0.12ms`. With no `--log`, print nothing (logging is slow, and the race measures speed).
3. Count requests per status code in `std::atomic<std::uint64_t>` counters, and print the totals on shutdown.

## Done when
- [ ] `--log` works; without it there is no output; the totals print on shutdown
- [ ] The `a_` tests still pass on `tsan` (the counters must be atomic)

- Why is `steady_clock` right for measuring durations and `system_clock` wrong?
