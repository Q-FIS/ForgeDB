# [W4.A3] The race: Group A's measurements
labels: week:4, size:M
groups: A

**Size:** M (2-3 days, 2 people) · **Needs:** W3.A5, W4.A1

## What is this, in plain words?
Both groups run **exactly the same** load tests on their servers, on the same
machine, and fill the same table. You run Group A's half; Group B runs theirs
(W4.B3); together you write the comparison (W4.C).

## The tests (both groups run exactly these, on the release build)
1. **Busy:** `wrk -t4 -c<C> -d30s --latency 'http://127.0.0.1:8080/sleep?ms=5'` for C = 10, 100, 1000. Record requests per second, p50 and p99.
2. **Fast:** the same against `/health`.
3. **Idle:** open 10,000 idle connections (`python3 tests/many_connections_test.py` shows how; you'll need `ulimit -n 20000`), then measure `/health` latency with `wrk -c100`. Also record the server's memory: the `VmRSS` line in `/proc/<pid>/status`, before and after.
4. **CPU:** during test 1 at C=100, the server's CPU use (`top -p <pid>`, or `pidstat`).

Use the same machine for both groups, with nothing else heavy running. Run each test 3 times and keep the median.
